# A Play Console listing as an organization

The steps to list NØNOS Wallet on Google Play under an organization account. Nothing here is
uploaded without the explicit word of the release key holder. Policies move, so read each page
of the Console again on the day.

## The account

1. Get a D-U-N-S number for the organization, free from Dun and Bradstreet. It can take weeks.
2. Create an organization developer account at play.google.com/console with that number, the legal
   name and address as they appear in the D-U-N-S record, a public email and phone, and the
   one-time registration fee. Google verifies the organization and a contact person.
3. Turn on two-step verification for every person on the account. Give others the least role they
   need. Only the key holder uploads. An organization account skips the closed test with twelve
   testers for fourteen days that newer personal accounts need.

## Signing on Play

Play takes a bundle, and with Play App Signing it signs the APKs it delivers. Two keys are involved.

| Key | Who holds it | What it signs |
|---|---|---|
| upload key | the key holder, a second key made like the release key in [04-release.md](04-release.md), alias `upload` | each bundle uploaded |
| app signing key | Google, generated by Play when the app is created | every APK Play delivers |

Keep the GitHub release key apart from both. Handing it to Play would let Play sign an update that
installs over a GitHub install. The cost: a Play install and a GitHub install have different
signers, so moving between them is an uninstall, a reinstall and a restore from the recovery words.

Signing the bundle of a tag with the upload key:

```sh
gh release download v1.2.3 -R NON-OS/shield-android -p 'NONOS-v1.2.3-unsigned.aab*'
shasum -a 256 -c NONOS-v1.2.3-unsigned.aab.sha256
jarsigner -keystore ~/keys/nonos-upload.p12 -sigalg SHA256withRSA -digestalg SHA-256 \
    -signedjar NONOS-v1.2.3-play.aab NONOS-v1.2.3-unsigned.aab upload
jarsigner -verify NONOS-v1.2.3-play.aab
```

## The listing

| Field | Value |
|---|---|
| App name, short and full description | `fastlane/metadata/android/en-US/` |
| Category | Finance |
| Icon, 512 by 512 PNG, and feature graphic, 1024 by 500 | drawn from `res/drawable/nonos_icon.xml` |
| Phone screenshots, two to eight | from the release build with Settings, Allow screen recording on, taken by hand |
| Privacy policy | a public page on the site, saying what [02-app.md](02-app.md) and the leak ledger of the core say |
| Contact | team@nonos.systems |

## App content

- **Ads**: none. **Target audience**: 18 and over. **App access**: nothing is behind a login. A
  reviewer makes a wallet on first launch. Say that the shield runs on Sepolia.
- **Financial features**: a non-custodial cryptocurrency wallet. The keys are made and kept on the
  phone, and no server can move funds. Play asks custodial wallets and exchanges for licences in
  some countries, and this answer is why that does not apply.
- **Data safety**: no analytics, no identifiers, no crash reports. Declare the financial data the
  lander receives to land a spend, over Tor, not shared, required for sending. Everything else goes
  from the phone to public Ethereum servers over Tor, at the request of the user.
- **Content rating**: answer the questionnaire. There is no user content, chat or gambling.

## Shipping

Upload to the internal test track first, install from Play on two phones, run the test in
[09-tutorial.md](09-tutorial.md), then promote to production. The package targets API 36 and its
libraries are aligned for 16 KB pages, which Play requires of new uploads. For installs from
GitHub, register the package name `systems.nonos.shield` and the release certificate under
developer verification in the Console, which Google requires in more countries each year.
